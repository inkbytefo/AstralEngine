# AstralEngine M0 — İskelet ve Core Uygulama Planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modüler CMake iskeleti, `Astral::Core` modülü (log, handle pool, clock, job sistemi), testler, `find_package(Astral)` ile tüketilebilir kurulum ve CI.

**Architecture:** Her modül `astral_add_module()` ile tanımlanan ayrı bir statik kütüphanedir; bağımlılıklar yalnızca `target_link_libraries` ile, tek yönlü verilir. Public API `modules/<mod>/include/astral/<mod>/` altında, uygulama `modules/<mod>/src/` altında. Global state yok; her şey constructor ile verilir.

**Tech Stack:** C++20, CMake ≥ 3.24, Ninja, doctest (FetchContent), GCC 13 / Clang 18, GitHub Actions.

**Spec:** AstralEngine — PRD (Claude Docs: https://claude.ai/artifact/Ef7Go2r239isFjDVoRqrXm), bölüm 3, 4, 6, 7/M0.

## Global Constraints

- C++20, `CMAKE_CXX_EXTENSIONS OFF`, uyarılar: `-Wall -Wextra -Wpedantic` (MSVC: `/W4`), `ASTRAL_WARNINGS_AS_ERRORS` seçeneği CI'da ON.
- Namespace `astral::` (modül alt namespace'i yok; Core tipleri `astral::Logger` vb.).
- Public header'larda üçüncü parti tip yok. Singleton / global mutable state yok.
- CMake hedef adları: `astral_core`, alias `Astral::Core`. Seçenekler `ASTRAL_` önekli.
- Testler `ctest` ile koşar; her modülün kendi test executable'ı (`astral_core_tests`).

## Review Focus

1. Job kuyruğunda iş varken `JobSystem` yok edilirse: bekleyen işler bitirilir, deadlock/crash yok → Task 5 testi.
2. `JobSystem::wait()` bir job'un içinden çağrılırsa: kilitlenmez, bekleyen işleri kendisi yürütür → Task 5 testi.
3. Silinmiş handle ile erişim: `get()` `nullptr` döner, eski handle yeni nesneye asla erişmez → Task 3 testi.
4. Birden fazla thread'den aynı anda log: satırlar bölünmez/kaybolmaz → Task 2 testi.
5. Job içinde exception: program çökmez, `wait()` exception'ı çağırana yeniden fırlatır → Task 5 testi.
